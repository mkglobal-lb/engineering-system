# New Knowledge Inbox — صندوق المعرفة الجديدة

Use this as a temporary inbox. Do **not** immediately turn every new idea into a permanent rule.

## Entry Template

```markdown
## YYYY-MM-DD — [Topic]

### What I learned
...

### Why it may matter
...

### Source / Evidence
...

### Candidate classification
- [ ] Engineering principle
- [ ] Workflow improvement
- [ ] Code-agent prompt improvement
- [ ] Testing/review rule
- [ ] Security/data rule
- [ ] Architecture guidance
- [ ] Engineering term
- [ ] Project-specific only (do NOT add globally)

### Decision
Pending / Promote / Reject / Project-specific
```

## Promote a rule when supported by one or more of:

- observed incident or failure;
- repeated engineering problem;
- authoritative standard/guidance;
- material security/reliability/data risk;
- strong empirical evidence;
- recurring operational friction;
- architectural consistency requirement.

## Do Not Promote

- a trendy opinion with no context;
- framework-specific advice presented as universal;
- a project business rule;
- a preference that has no meaningful engineering consequence.
